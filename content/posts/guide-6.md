## 为什么要备份

网站内容都在 GitHub 仓库里，每一次提交都有记录，任何一篇文章、任何一章都能找回以前的版本。再定期下载一份备份到自己的设备上，就更稳妥了。

> [!IMPORTANT]
> 建议每写完一批内容就备份一次。超过 30 天没有备份，或者这台设备从来没备份过，进入后台时会出现提醒。

## 下载备份

在后台进入「写作 → 备份」，顶部显示现在一共有多少文章、小说、章节和图片。

- **完整备份（.json）**：包含所有文章、小说、图片和网站设置，用来恢复网站，也可以导入另一个仓库。
- **Markdown 文稿（.zip）**：每篇文章、每个章节都是单独的 .md 文件；小说按作品分文件夹，有分卷的再按卷分子文件夹；图片单独放一个文件夹。适合直接阅读，或者搬到其他平台，但不能用来恢复网站。

下载的文件会保存在浏览器默认的下载位置。

两种导出都会收集文章使用的站内图片，包括带标题的 Markdown 图片、引用式图片和 HTML 的 `img` / `srcset` 写法；相同图片只打包一次，图片说明和标题会保留。外部网站的图片链接保持原样，不会下载到备份中。

两种导出都会先读取文章使用的站内图片。只要有一张图片读取失败，就会停止导出并列出失败的文件名，不会下载缺图的备份；检查网络后重新下载即可。失败的导出不会更新「上次备份」时间。

## 从备份恢复

在「写作 → 备份」点「选择备份文件」，选一个 .json 备份。后台会先告诉你这份备份是什么时候的、包含哪些内容，再让你选：

- **只补回缺少的**：把现在没有、备份里有的文章、小说、章节和分卷加回来，现有的内容不动。适合找回误删的东西。
- **全部替换**：用备份覆盖现在的所有内容和设置。

> [!CAUTION]
> 「全部替换」会丢掉这份备份之后写的所有内容。不确定的话，先下载一份当前的备份，再替换。

## 用历史记录找回旧版本

在 GitHub 网页上打开仓库，找到 `content/posts` 或 `content/novels` 里对应的文件，点「History」就能看到每一次修改。点开某个版本复制内容，再到后台粘贴、发布即可。

## 使用限制

- 发布后要等 GitHub 生成网站，大约 1–2 分钟。
- 仓库是公开的，草稿也能被别人看到。
- 照片上传前会自动压缩，一般在 200KB 以内。仓库和网站的总大小建议不超过 1GB。
- 访问令牌只保存在当前设备上，换设备需要重新连接。
- 目前没有评论、访问统计和定时发布。

## 常见问题

**打开后台要我填访问令牌？**
第一次在这台设备上使用时需要填，之后会记住。令牌的创建方法见部署说明。

**提示「访问令牌无效、已过期」？**
令牌到期了或者被删了。到 GitHub 重新创建一个，在后台「写作」页面顶部的「连接设置」里换上。

**手机丢了怎么办？**
到 GitHub 的令牌设置里，把那台手机用的令牌删掉，它就不能再修改网站了。

**点了发布，网站上还没变？**
等 1–2 分钟。后台底部会显示进度；如果显示「网站生成失败」，点「查看原因」。

**提示「这些内容刚在别处被修改过」？**
你可能在另一台设备上，或者在 GitHub 网页上改过同一篇。后台已经载入了最新版本，你写的内容还在这台设备的草稿里，打开编辑器恢复后再提交即可。

**某个标签找不到？**
标签栏默认只显示最常用的 12 个，点「全部 N 个标签」展开。

**刚打开网站时，字体跳了一下？**
页面会先用手机自带的字体立刻显示，网页字体下载好后再换上，这是正常的。

**想找回删掉的文章？**
用删除之前下载的完整备份，选「只补回缺少的」；或者在 GitHub 的历史记录里找回。
